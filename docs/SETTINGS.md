# Settings and preview

Settings apply immediately. Visual pages include a preview generated by the same native builders as the running HUD. It uses sample data, not conversations or API credentials. Select Summary, List, Bubble, Quiet or Message to inspect a surface; Play effects demonstrates its configured reminder. Hide collapses the preview to give controls more room.

## What changes which surface?

| Setting | Scope |
| --- | --- |
| Appearance: theme, type, opacity, colors | HUD surfaces; notices remain readable on an opaque shell |
| Main bubble layout | Summary header only |
| Bubble density | Padding and gaps in the main bubble, task rows and detached bubbles; layout, type and fields stay unchanged |
| Task list style, details | Expanded task list only |
| Task names | List identities and detached bubble identities |
| Detached bubble fields | Detached bubbles only |
| Main status dot | Summary dot; task dots keep their own state and effects |
| Corner drag on the main bubble | Extra padding and spacing, above the selected layout's defaults |
| Corner drag on a detached bubble | That bubble's size |

## General

Language, position, topmost and click-through control the running HUD. Token totals selects the latest task's counts or the sum of visible tasks; it does not filter the task list or multiply account allowance. Inactive retention hides ordinary tasks after inactivity; waiting tasks and running turns have separate retention rules. Completed-task retention and departure effects act after a terminal event.

Always on top is maintained by the native window layer across showing, hiding, geometry changes and quiet transitions, without waiting for a repaint or taking keyboard focus. Turning it off explicitly returns the HUD to the normal window layer. Settings and their popups keep their own ordering above the overlay.

Number format applies to token numbers, including the activity rhythm total. A blank pricing path selects the bundled catalog; a local catalog changes estimates, not subscriptions or account balances. Reset restores configuration and theme selection while retaining installed theme files, pricing files and saved API keys.

## Appearance

Themes apply immediately, including imported themes. Font size, shell corners, opacity, foreground, accent and status colors preview live. A background color is the fallback for a theme that uses an image or gradient. Uniform opacity affects the whole HUD surface; layered opacity keeps text stronger than the shell; focus opacity responds to activity. Task-change fades and reminder effects are separate controls.

Opacity increases from transparent to opaque. At 100%, solid and gradient backgrounds are fully opaque in every mode; theme alpha no longer imposes a hidden upper limit. Lower values change continuously. Layered uses two curves: background and decoration alpha = opacity, while all information (text, icons, numbers and status) uses opacity^0.35. At 50% the shell is 50% opaque and information is about 78%; at 20% information retains about 57%. Both reach zero at 0%. Focus further fades idle states. Tinted controls follow the decoration curve.

## Main bubble

Choose the layout here, then choose its lead: token metrics, activity rhythm or no lead. Only the relevant lead controls are shown. Task summary and account allowance remain separate sections. Cards place labels above values for metrics, rhythm, task counts and allowance groups. Vertical groups stack instead of laying out a horizontal strip. Other layouts wrap when screen width requires it.

Allowance style controls per-agent meters versus individual labeled readings. Only agents with active, listening or waiting tasks appear in the main bubble; completed and idle tasks do not keep an account group visible. The DeepSeek CLI profile belongs to the DeepSeek balance group. Hide missing readings removes unavailable account values, not zero balances. The waiting badge highlights tasks needing input. Extra spacing changes padding and gaps without scaling the type.

Compact readings is an optional quota style: agent icon, 5-hour / weekly percentages, or just the DeepSeek Harness balance. It retains the same availability filters, colors and individual field switches as the meter style. With only one window visible, its short label remains to avoid ambiguity. Agent names are abbreviated as Codex, CC and DSH only in the main bubble; other surfaces keep their full names.

## Tasks

The default display mode can be Summary, List or Detached. The summary arrow temporarily expands or collapses the list; choosing a new mode in Settings takes precedence over that temporary state.

List style changes structure; bubble density changes padding, row height and button spacing across the HUD; list details changes the metrics shown. Compact, balanced and relaxed keep the same identity lines, typography and content. Context badges remain visible in the list; the context visibility switch controls detached bubbles.

Task numbers, names and context badges share content-measured column widths within each list, so short titles and changing percentages do not shift the neighboring columns. The settings preview uses the same spacing and column alignment as the live list, including additional corner-drag spacing. Disclosure and task action buttons share their size and corner treatment; informational badges use lighter surfaces without button-like outlines.

Detached bubbles have separate field choices and a count limit from 1 to 12. Reducing the limit merges excess bubbles. Automatic splitting applies to new tasks in Detached mode. Number reuse cooldown reserves retired task numbers and can be set to immediate reuse.

Quiet mode retracts after inactivity and expands on hover or new work. A small neutral capsule replaces the full bubble; its status mark has no accent ring. Interface transitions animate the shell size and position while fading the content without stretching type. The preview can demonstrate both directions without waiting for the inactivity timer. Quiet size does not inherit the expanded bubble's extra spacing. Task-light shape is relevant only for the horizontal and vertical variants.

## Alerts

Completion, interruption/error, waiting and sustained quiet are distinct triggers. Summary, list-row and detached-bubble surface effects are independent; dot pattern, brightness, speed and breathing control the task status lights. The preview demonstrates effects locally and sends no notices to tasks.

Context alerts use per-task thresholds. Enabling alerts also enables the detached context display; hiding that display disables the alerts. Showing it alone does not turn alerts back on. Changing unrelated appearance settings preserves an existing context alert's progress.

Agent notices require the feature to be enabled. Permission, effect, color, intensity and duration configure their card. The allowance handoff guard is for Codex account allowance at agent checkpoints; it does not automatically interrupt generation or apply this guard to Claude or DeepSeek. Thresholds use remaining percentages, and handoff thresholds cannot exceed preparation thresholds.

## Agents

Source switches filter local task monitoring. Codex and Claude subscription readings are account-level values with observation times. DeepSeek balance requires a saved key; its row distinguishes pending, successful and failed reads. Account updates refresh an open settings window even when there is no visible task. The key is stored separately from the settings document.

Codex uses the newest observation per quota window, with background reads every 30 seconds while active and every 2 minutes while idle. DeepSeek checks every 30 seconds during activity, every 5 minutes when idle, and shortly after a turn ends. Opening Settings requests both reads with a short throttle. Claude Desktop file changes are detected in about 1–2 seconds; the desktop app still determines when it samples upstream usage. A temporary read failure retains the last successful observation and its real timestamp.

### API price estimates

The bundled catalog was checked on 2026-10-27 against the [OpenAI](https://developers.openai.com/api/docs/pricing), [Claude](https://platform.claude.com/docs/en/about-claude/pricing) and [DeepSeek](https://api-docs.deepseek.com/quick_start/pricing/) documentation. It includes GPT-6.1 Sol/Terra, the GPT-6 and GPT-5.6 families, the Claude models exposed by the current selector, and DeepSeek Flash/Pro with their documented aliases. Sonnet 5.5 cache reads use $0.10 per million tokens.

Request prompt size, including cached tokens and cache writes, selects the long-context tier: above 272,000 for the listed GPT-6/5.6 models (2x input/cache and 1.5x output), and above 100,000 for Haiku 5.5 (5x all token rates). Claude responses are priced independently and deduplicated across streaming blocks; switching models does not reprice earlier responses.

DeepSeek peak periods are 01:00–04:00 and 06:00–10:00 UTC on weekdays, excluding Chinese public holidays. Weekends and holidays are entirely off-peak. The bundled schedule contains the official 2026 holiday ranges and is independent of the PC time zone. A future year without a holiday calendar stays unknown during potential peak periods. Update the local catalog schedule when the official next-year calendar is available.

Small local `price-checkpoints.json` records retain cumulative token/cost checkpoints across restarts, not message contents. Newly observed increments retain the applicable model/time rate; changing appearance or crossing a peak boundary does not reprice earlier tokens. Pre-observation Codex cumulative history remains a standard short-context estimate because tail hydration lacks complete per-request metadata. DeepSeek projections expose totals and the latest usage, so older multi-call history without timestamps remains `--`; skipped checkpoints crossing tariffs also stay unknown. A new session observed from its first call can accumulate time-based estimates. DSH uses its latest message metadata timestamp as the request-time approximation.

Standard text-token estimates exclude unreported processing tiers, regional surcharges and server tools. DeepSeek Search/Fetch becomes billable on 2026-11-01 at 00:00 Beijing time ($0.75 per 1,000 successful requests); these counts are not present in the monitored projection and are excluded. Account balance is queried independently and remains the authoritative balance.

### TPS

`Multi-task > Task list > TPS` controls both list rows and detached task bubbles and defaults on. The main summary is unchanged. The first valid sample is shown immediately, then numerical updates are coalesced to 30 seconds. The calculation uses settled output and timing records. Tools with observed pending calls and non-active task states display `0`; unmatched or missing timing data displays `--`. Hover the task metrics for the source basis, sample count and sample time.

- Codex uses up to 5 valid completed responses in the past 5 minutes. Response output counts include reasoning; recorded model-item output windows exclude tool execution. Duplicate usage feeds do not count twice. A bounded 512 KiB timing tail restores recent samples on restart.
- Claude Code correlates `api-request.id` with `assistant.requestRef`, deduplicates response blocks, and uses up to 5 requests in 5 minutes. Its denominator includes request/first-token latency and excludes tools between requests. Older transcripts without matched request metadata remain unavailable. Existing transcript parsing supplies this metadata; no statusline or hook is replaced.
- DeepSeek Harness uses its native `sessionStats.decodeTokens / decodeMs`, excluding time to first token and tools. This is the native session decode average rather than a five-response reconstruction. Observed model changes establish a new counter baseline.

No extra network calls, tokenizer, agent restarts, whole-history scan or persistent message cache is added. State is bounded per task. A read-only `AgentMonitorHUD.exe speed-check codex|claude|dsh <file> [as-of-unix-ms]` diagnostic reports counts and the same calculation used by the UI, without message bodies; the optional timestamp is for historical record inspection.
